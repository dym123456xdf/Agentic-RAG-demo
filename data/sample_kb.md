# 个人知识库 - 测试样本

## 第一章：Modular RAG 是什么

Modular RAG 是一种把检索增强生成流水线拆成多个独立模块的设计思路。每个模块有自己的职责：配置中心、索引构建、查询预处理、文档召回、检索后处理、答案生成。这种设计让每一段都可以单独替换或调参。

## 第二章：五大核心模块

1. **配置中心**：统一管理 LLM API、Embedding 服务、Milvus 连接等所有外部依赖的连接信息。
2. **索引构建**：把原始文档加载、切分、向量化后写入 Milvus 向量库。
3. **查询预处理**：对用户原始问题做意图识别、多轮改写、查询扩展，提升召回质量。
4. **文档召回**：基于预处理后的 query 从向量库捞相关片段，提供混合检索和纯向量两种策略。
5. **检索后处理**：用相似度阈值过滤掉明显不相关的片段，再用 BGE 重排序模型重新打分排序。
6. **答案生成**：把重排后的高质量片段拼成上下文，连同用户问题一起交给 LLM 生成最终回答。

## 第三章：为什么用 BGE-reranker

- 速度比 LLM 重排快约 30 倍
- 成本便宜 10 到 20 倍
- 对中英双语 query-doc 相关性判断更准

代价是首次加载需要几秒到十几秒（模型约 2.2GB），加载一次后复用。

## 第四章：FastAPI 怎么搭

FastAPI 是一个基于 Python 类型注解的现代 Web 框架。可以用 uvicorn 运行，提供自动的 OpenAPI 文档（/docs）。常见模式是用 APIRouter 拆分路由模块，最后在主入口用 include_router 挂上去。
